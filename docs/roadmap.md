# 实施路线与验收点

本路线将已有底盘、机械臂和模型实验连接为可逐步验证的系统。顺序可根据设备和实验条件调整；阶段标题表示目标，不表示已完成。项目正式研究范围和申报表述以 [项目文档仓库](https://github.com/ianhequn/da_chuang_20261112) 为准。

## 阶段 0：证据与接口盘点

- 为各仓库列出 ROS 2 版本、运行设备、输入输出、可复现实验和依赖。
- 确认现有 2D 雷达、IMU/轮速、腕部 RGB 与机械臂反馈各自的驱动、频率和时间戳来源。
- 明确仿真和真机实际可用的传感器；深度相机与 3D 雷达属于后续扩展，不写成当前已具备条件。

**验收：**每项“已实现”能力能指向具体仓库、命令或测试记录；未知项保留为待测。

## 阶段 1：常见传感器观测接口

先选一个最小跨环境样例，例如仿真与真机的 2D 激光雷达。适配器记录：

| 字段/约束 | 用途 |
| --- | --- |
| `sample_time`、`receive_time`、`clock_id` | 区分采样与到达，避免混用仿真时钟和系统时钟 |
| `frame_id`、外参/TF | 说明数据所在坐标系及其到机器人基座的变换 |
| 单位、采样率、序号、有效性 | 防止单位误读、过期数据和丢帧被当成新观测 |
| 标定版本、设备状态 | 使几何计算和故障追踪有依据 |

高频原始数据通过 ROS 2 话题或适合的存储/传输方式提供；上层使用摘要、索引和受控查询工具。JSON 用来表达配置及观测元数据，不承担相机或雷达原始数据流。

**验收：**同一个读取接口可读取两种来源的同类传感器数据；记录实际采样率、延迟、时间偏差、丢帧和过期拦截情况，并能复现故障注入测试。

## 阶段 2：空间关系与技能服务

- 校核相机/雷达到机器人基座的安装外参及 TF；真机按设备情况检查内参、深度对齐和标定。仿真使用配置中的参数，也要核对 frame 与时间基准。
- 将导航、视觉搜索和机械臂动作整理为可调用能力，说明输入、前置条件、状态、取消、超时和失败原因。
- 初期采取底盘停车后再操作，降低移动与操作的耦合。

**验收：**每项技能能单独调用、报告结果和失败，且不会因旧观测或坐标错误继续执行危险的动作。

## 阶段 3：环境认知与 Agent 任务编排

- 建立可查询的区域、物体、最近观测和候选位置记录；保留时间、来源与不确定性。
- Agent 读取环境服务和能力说明，发起技能调用，并处理完成、失败、用户改动和环境变化等事件。
- 先用模拟服务测试调度和状态，再逐步接入仿真与真机能力。

**验收：**能够追溯一次决策使用的环境信息、技能状态和反馈；失败后可安全停止、调整或请求帮助。

## 阶段 4：受控场景的寻物取回实验

在有限物品、受控室内区域中验证“提出目标 → 查询/搜索 → 导航 → 抓取放置 → 返回 → 更新环境状态”。分别记录分段结果和完整任务结果；重复实验并观察耗时、成功率、人工干预、定位误差和失败原因。调用返回或夹爪释放不能单独算作物理取回成功。

**验收：**具备可重复运行的任务与结果记录，能说明哪些环节仍由人工介入，哪些改动改善了整机表现。

## 后续扩展

在首期闭环稳定后，再比较新增传感器、技能或平台的适配工作量和性能变化。自动生成 skill、深度相机、多摄像头、3D 雷达和更多家居服务均是候选方向；是否开展及效果需要另行实验，不能从现有仓库推定。
